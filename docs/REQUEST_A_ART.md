# 依頼書 A: こひとの仮絵の描き分け v1.0

対象: Codex CLI（実装担当）
前提: [docs/HANDOVER.md](./HANDOVER.md) §6（地雷）と §7-A を読んでから着手すること。
この依頼書で数値が指定されている箇所は、**勝手に変えないこと**。
指定がない見た目の細部は、この依頼書の方針に沿って判断してよい。

## 0. 目的

今の仮絵は色と質感は良いが、**形の描き分けができていない**。
ウラスミ／ハリツキ／ドブノゾキ／ノボリユラシの4体が「灰色の胴＋淡い楕円の頭＋目＋足2つ」という
同じシルエットで、差分は目の数・胴の太さ・腕だけ。ゲーム中の実寸（高さ 30px 前後）では見分けがつかない。
また、物語の芯が「しずく（水）」なのに、**濡れの表現がどこにもない**。

この依頼でやること:

1. 6体それぞれを、**塗りつぶした影絵（シルエット）だけで見分けられる**形にする。
2. 6体それぞれに「濡れ」の表現を1つ以上入れる。
3. 全員に同じ位置で描かれている白い点（`kohitoArt.ts` の `ellipse(c, 4, -6, 3, 1.5, P.white)`）をやめる。
4. たれじりの全身状態で、胴と尻がつながって見えるようにする。

**ゲームのルール、採点、当たり判定、出現条件は一切変えない。**

## 1. 絶対に守る制約

1. 変更してよいファイルは次だけ。
   - `src/render/kohitoArt.ts`（主な作業場所）
   - `src/render/palette.ts`（色の**追加**のみ。既存の色の値は変えない）
   - `tests/art.test.ts`（新規。§5）
   - `tools/art-preview.html`（新規。§6）
   - `docs/HANDOVER.md`（§7-A を「対応済み」に更新する）
2. `drawKohito` / `drawPlayer` の**関数名・引数・引数の意味を変えない**。
   呼び出し元（`field.ts` / `camera.ts` / `album.ts` / `ending.ts`）は触らない。
3. 外部アセット（画像・SVGファイル・フォント）を使わない。Canvas 2D の図形描画のみ。
4. 依存ライブラリを増やさない（`devDependencies` は `typescript` / `vite` / `vitest` のまま）。
5. 1体あたりの描画命令は**おおむね30個以内**（`fill` / `stroke` の回数で数える）。
   PC側の検証環境はソフトウェア描画で遅いので、重い表現（グラデーションの多用、`shadowBlur`、
   `filter`、毎フレームのパス大量生成）は使わない。
6. **§2 の描画範囲から絶対にはみ出さない。**（採点と遮蔽がこの範囲を前提にしている。§5 のテストで守る）
7. 既存作品との差別化方針を守る（HANDOVER.md §4）。
   特にたれじりの尻は**桃型にしない**（割れ目・ハート形・ピンク系は禁止）。
   餅／水まんじゅうのように**下へ垂れて伸びる半透明**のかたまりにする。
8. 気持ち悪さは「ゆるキモ」まで。流血・傷・内臓・虫の脚の多用などグロテスクな表現は使わない。

## 2. 描画範囲（採点と連動しているので厳守）

座標は `drawKohito` 内のローカル座標（`translate(x, y + 上下ゆれ)` の後）。
原点 (0, 0) はこひとの立ち位置で、+y が下。足元の影 `ellipse(0, 12, 15, 4)` は今のまま残してよく、範囲の判定から除く。

| 対象 | 状態 | 描いてよい範囲（x の最小〜最大, y の最小〜最大） | 根拠 |
|---|---|---|---|
| たれじり以外の5体 | すべて | x: **-20 〜 24**, y: **-30 〜 16** | `src/scenes/camera.ts:19` の被写体矩形 `{left:-20, top:-30, w:44, h:46}` |
| たれじり | 全身（`hidden=false`） | x: **-15 〜 20**, y: **-37 〜 25** | 同 `{left:-15, top:-37, w:35, h:62}` |
| たれじり | 隠れ（`hidden=true`） | x: **-6 〜 20**, y: **-7 〜 20** | `src/scenes/camera.ts:30` の「見えている尻の範囲」 |

- 決定的瞬間（`special=true`）の絵も同じ範囲に収める。
- 揺れやしずくのアニメーション（`elapsed` で動くもの）も、**どの時刻でも**範囲に収める。
- この範囲を広げたい場合は、この依頼の範囲外。勝手に `camera.ts` / `field.ts` を変えずに、
  レポートに「範囲が足りない」と書いて止めること（HANDOVER.md §6 地雷3）。

## 3. 6体のデザイン

### 共通の方針

- **シルエットの軸を「高さ × 横幅 × 突起」で散らす。** 下の表の目標値（ローカル座標の単位）に合わせる。
- 頭と胴を「楕円2つの雪だるま」で作るのは**ドブノゾキ以外禁止**（今の量産型シルエットの原因）。
- 色は今のパレット（くすんだ灰緑・淡い黄緑・半透明）を基調に、体ごとに1色だけ差し色を許す（任意）。
- 目は「多すぎるか少なすぎるか」のどちらか（MVP_SPEC §10 の方針を継続）。

### 目標シルエット

目標値は、§5 のテスト3（どの2体も幅か高さが 6 以上違う）を満たすように組んである（検算済み）。

| id | 名前 | 高さの目標 | 横幅の目標 | シルエットの一言 | 主な突起・特徴 |
|---|---|---|---|---|---|
| `urasumi` | じはんきウラスミ | **20〜24**（低い） | **36〜42**（横に広い） | うずくまった だんご | 片腕だけ異様に長く細い。指が3本、関節が多い |
| `haritsuki` | シャッターハリツキ | **40〜44**（高い） | **16〜20**（薄い） | 縦長の板 | 体に横縞（シャッターの模様）。縦に細い目 |
| `dobunozoki` | ドブノゾキ | **14〜18**（いちばん低い） | **24〜28** | 地面から出た半円ドーム | 大きく飛び出た目玉3つ。体の下半分は地面に埋まって見えない |
| `noboriyurashi` | ノボリユラシ | **42〜46**（いちばん高い） | 体は **6〜8**、布を含めて **30〜40** | 細い棒＋たなびく布 | 棒のような胴の片側に、のぼり旗のような薄い皮膚がひらひら揺れる |
| `kagebousi` | ダンチカゲボウシ | **30〜34**（今の 43 から縮める） | 18〜26 目安 | 傾いた影 | 影の中に目だけが浮かぶ（白目なし、点2つ） |
| `tarejiri` | かくれたれじり | 全身 **55〜60** | **30〜35** | 前かがみの小さな上半身＋大きく垂れた尻 | 尻は半透明で下へ垂れる。胴から尻へ切れ目なくつながる |

### 1体ずつ

**じはんきウラスミ（自販機の裏・夜）**
- 背中を丸めて横に長い だんご状。頭は胴に埋まっていて、境目がない。目は1つ、小さく横長。
- 片腕だけが長く、関節2つで折れ曲がり、先に細い指が3本。もう片方の腕は無い（または小さな こぶ）。
- 濡れ: 指先にしずく1つ（`P.water`）が付いていて、光る点（白）がある。
- 決定的瞬間「指を舐める」: 長い腕を口元へ曲げ、口（横長の楕円）から舌が出る。指先のしずくが消える。

**シャッターハリツキ（閉店した店のシャッター・昼）**
- 縦長の薄い板。角の丸い長方形（`roundRect` があればそれ、無ければ楕円とパスで）に近い輪郭。
- 体に**横縞を4〜5本**（シャッターの溝）。そのうち1本だけが呼吸に合わせて太さが変わる
  （`Math.sin(elapsed * 2)` 程度の周期）。
- 目は縦に細い楕円2つを、縞と縞の間に。
- 濡れ: 板の下端に、結露のような小さなしずくが2〜3個ぶら下がる。
- 決定的瞬間「シャッターから半身をはがす」: 板の上半分が手前へ めくれ（平行四辺形などで表現）、
  裏側の湿った肌（差し色、少し暗い灰緑＋白い光沢点）が見える。**頭が2つあるように見えないこと**
  （今の絵はここが読めない）。

**ドブノゾキ（側溝のふたの穴・朝）**
- 地面から上だけが見えている半円のドーム。下端は水平にまっすぐ切る（地面の線）。
- 目玉3つが ドームの上端から**飛び出している**（輪郭の外へはみ出す丸）。目は白目＋大きな黒目＋光。
- 濡れ: ドームの上に苔のような湿ったテカリ（細長い白い光沢）＋目の潤み（光を大きめに）。
- 決定的瞬間「あくび」: ドームの正面に大きな口（暗い楕円）が開き、目玉3つがぎゅっと閉じる（横線）。

**ノボリユラシ（商店街ののぼり旗・夕）**
- 胴は細長い棒（幅6〜8、高さ42〜46）。上端に小さな頭（棒と同じ幅か少し太い程度）。
- 棒の片側（右）に、薄い布のような皮膚が1枚ついていて、**風がないのに揺れる**
  （布の外側の辺を `Math.sin(elapsed * 3 + 位置)` で波打たせる）。布は差し色に色あせた赤系を薄く使ってよい。
- 目は棒の上のほうに縦に3つ並ぶ（多すぎる目）。
- 濡れ: 布の下端から汗のしずくが1つ、周期的に落ちる（範囲内で消える）。
- 決定的瞬間「大きく揺れる」: 布が大きくはためき、棒全体も傾く。**範囲 x ≤ 24 を超えないこと。**

**ダンチカゲボウシ（団地の踊り場・夜）**
- 今の傾いた影の形はよいので維持する。ただし**高さを 30〜34 に縮める**。
  今の絵は高さ約 43 でハリツキ（40〜44）と区別できず、しかも下端が y = 16.6 まで出ていて §2 の範囲（y ≤ 16）を
  すでにはみ出している（検算済み）。縮めたうえで範囲に収めること。
- 頭の位置にある白い点1つを、影の中に浮かぶ**目2つ**（小さな白い点、白目なし）に変える。
- 濡れ: 影の足元に、湿った染み（半透明の `P.water` の楕円、影より少し大きい）。
- 決定的瞬間: 今の「横に伸びる」を維持し、目が4つに増える。

**かくれたれじり（川沿い・夕）**
- 全身: 小さな上半身が前かがみに立ち、腰から後ろへ大きな尻が**垂れ下がる**。
  胴の下端と尻の上端を、**半透明の楕円かパスで重ねてつなぐ**（今は胴と尻が別物に見える）。
- 尻は3段以上の半透明の楕円を下へずらして重ね、下ほど細くなる（水まんじゅうが垂れる形）。
  `globalAlpha` 0.55〜0.7 程度。光沢点（白）を1つ。
- 濡れ: 尻の最下端から しずくが周期的に落ちる（`special` のときは常に落ち続ける）。
  しずくも §2 の範囲内で消すこと（全身 y ≤ 25、隠れ y ≤ 20）。
- 隠れ（`hidden=true`）: **尻だけ**を描く。胴・頭・腕は描かない。
  尻の形と位置は全身のときと同じにする（隠れ→全身で尻が跳ばないように）。
- 範囲は §2 のたれじり専用の値。**ここが一番の地雷**（HANDOVER.md §6 地雷3）。

## 4. 実装の進め方（推奨）

1. `tools/art-preview.html` を先に作る（§6）。これで見比べながら描く。
2. 共通の白い点を消し、`else` ブランチ（4体共通の描画）を**体ごとの関数に分割**する。
   例: `drawUrasumi(c, elapsed, special)` … のように、`drawKohito` から id で振り分ける。
3. 1体ずつ §3 の形にする。各体を描いたら、プレビューの影絵モード（§6）で見分けられるか確認する。
4. `tests/art.test.ts` を書き、範囲を守っていることを確かめる（§5）。
5. 最後に `npm run typecheck && npm test && npm run build`。

コミットは「プレビュー追加」「体ごとの関数に分割」「各体の描き直し」「テスト追加」くらいの単位で分けてよい。
コミットメッセージは日本語でよい。

## 5. テスト（`tests/art.test.ts`、Vitest）

絵の良し悪しはテストできないが、**範囲を守っていること**と**描き分けの最低条件**はテストで守る。

### 記録用の偽コンテキスト

Vitest は Node で動くので本物の canvas は無い。`CanvasRenderingContext2D` の代わりに、
描画命令を受け取って**塗った図形の外接矩形をローカル座標で記録する**偽オブジェクトを作る。

- 対応するメソッド: `save` / `restore` / `translate` / `scale` / `rotate` / `beginPath` / `closePath` /
  `moveTo` / `lineTo` / `quadraticCurveTo` / `bezierCurveTo` / `arc` / `ellipse` / `rect` / `roundRect` /
  `fill` / `stroke` / `fillRect` / `strokeRect`、プロパティ `fillStyle` / `strokeStyle` / `lineWidth` /
  `globalAlpha` / `lineCap` / `lineJoin`。
- 変換（translate / scale / rotate）は行列で追跡し、`save` / `restore` で戻す。
- パスの点（曲線は制御点も含めてよい＝外側に安全側）を変換してから外接矩形に加える。
  `ellipse` は回転を考慮して外接矩形を出す（各軸の半径の最大で近似してよい）。`stroke` は `lineWidth / 2` を足す。
- `drawKohito(ctx, id, 0, 0, elapsed, special, hidden)` を呼び、上下ゆれの分（`translate` の y）を差し引いて
  ローカル座標の範囲を得る。**足元の影の楕円（`P.shadow` で塗ったもの）は除外する。**
- 偽オブジェクトは `as unknown as CanvasRenderingContext2D` で渡してよい（`any` は使わない）。
  実装が使うメソッドが足りなければ偽オブジェクト側に足すこと。

### 必ず書くテスト

1. **範囲**: 6体 × `special` の真偽 × `elapsed` を 0〜6 秒で 0.1 秒刻み（61点）すべてで、§2 の範囲に収まる。
   たれじりは `hidden` の真偽の両方を確かめ、それぞれの範囲で判定する。
2. **共通の白い点がない**: たれじり以外の5体で、中心 (4, -6)・半径 (3, 1.5) の白い楕円を描いていない。
3. **シルエットが散っている**: `special=false`, `elapsed=0` の外接矩形について、
   - 高さが §3 の目標の範囲に入る（6体すべて。たれじりは全身）。
   - たれじり以外の5体で、外接矩形の（幅, 高さ）がどの2体の組み合わせでも
     **幅か高さのどちらかが 6 以上違う**。
4. **隠れたれじりは尻だけ**: `hidden=true` のとき、`x < -6` または `y < -7` の領域に何も塗らない。

既存の87件のテストは1件も壊さないこと（特に `playthrough.test.ts` の「隠れた尻だけでは全身にならない」）。

## 6. プレビューページ（`tools/art-preview.html`）

`npm run dev` 中に `http://localhost:5173/tools/art-preview.html` で開ける静止ページ。
`/src/render/kohitoArt.ts` を import して、次を1枚に並べる。

- 1段目: 6体を **4倍**で、通常の絵。
- 2段目: 6体を **4倍**で、決定的瞬間（`special=true`）。
- 3段目: 6体を **実寸（1倍）**で、通常の絵。背景はゲームの地面の色（`P.sand`）。
- 4段目: 6体を **実寸**で、**影絵モード**（すべて `P.ink` で塗りつぶし。偽コンテキストか
  `globalCompositeOperation` を使う）。**この段で6体を見分けられることが今回のゴール。**
- 5段目: たれじりの `hidden=true` と `false` を並べ、§2 の範囲の矩形を枠線で重ねて表示する。
- `elapsed` を進めるボタン（または `requestAnimationFrame` で数秒だけ動かす）を付けてもよい。

このページは `vite build` の成果物には入らない（`index.html` だけがビルド対象）。リポジトリには残す。
