対象: Codex CLI（実装担当）
前提: [docs/GAME_DESIGN.md](./GAME_DESIGN.md) v0.4 を読んでから着手すること。
この指示書で数値や文面が指定されている箇所は、**勝手に変えないこと**。

## 0. 絶対に守る制約

1. **外部アセットを一切使わない。** 画像ファイル・音声ファイル・Webフォントを置かない。
   絵はすべて Canvas 2D の図形描画、またはコード内のインライン SVG パスで描く。
2. **実行時依存ライブラリを増やさない。** ゲームライブラリ（Phaser 等）は使わない。
   `dependencies` は空。`devDependencies` は `typescript` / `vite` / `vitest` のみ。
3. **ネットワーク通信をしない。** fetch / XHR / WebSocket を書かない。オフラインで完結する。
4. **UI とフレーバーの日本語はすべて `src/data/text.ts` に集約する。** 他のファイルに
   日本語の表示文字列をハードコードしない（コメントは日本語で書いてよい）。
5. **実在の地名・店名・施設名を使わない。** まちの名前は「あつぎ」（ひらがな）で統一。
6. TypeScript は `strict: true`。`any` は使わない（どうしても必要なら `unknown` + 絞り込み）。
7. 完了前に `npm run typecheck` / `npm test` / `npm run build` の3つを通すこと。

## 2. 画面と入力

### 論理解像度

- 内部論理解像度は **360 × 640**（縦）固定。すべての座標計算はこの単位で行う。
- 実際の canvas は `devicePixelRatio` を掛けたサイズにし、CSS で画面に収まるよう
  アスペクト比を保ったまま拡大（レターボックス）。横画面でも縦のまま中央に出す。
- タッチ座標は論理座標へ逆変換するユーティリティを `canvas.ts` に用意する。

### 入力

| 操作 | スマホ | PC |
|---|---|---|
| 移動 | 画面左下の仮想スティック（半径 44、ドラッグで方向） | WASD / 矢印キー |
| 忍び足 | スティックを中心から **半分以下**しか倒していない状態 | Shift 押下 |
| カメラを構える／ピント | 画面右下のカメラボタンを**長押し** | スペース長押し、またはマウス長押し |
| シャッター | 長押しを**離す** | 同じ |
| カメラをやめる | カメラ画面の「やめる」ボタン | Esc |
| アルバム | 画面右上のボタン | Tab |

- スティックとカメラボタンは**どちらも同時に使える**こと（マルチタッチ。`pointerId` で管理）。
- 移動入力が無い間、プレイヤーは静止扱い（足音ゼロ）。

## 3. 場面（シーン）

`GameState.scene` で切り替える。

1. `title` — タイトル「こひとさがし」。「はじめる」「つづける」（セーブがあるときだけ）。
2. `map` — まちの地図。現在の日数と時間区分を表示。4スポット＋「いえ（かえる）」を選ぶ。
   - スポットを選んで**移動すると時間が1区分進む**（§4）。
3. `field` — 散策（見下ろし視点）。
4. `camera` — カメラ画面（`field` から遷移。プレイヤーは移動できない）。
5. `album` — あつぎこひと観察アルバム。タブ3枚:「しゃしん」「メモ」「すいり」。
6. `dayend` — その日のまとめ（夜の散策を終えて帰宅したとき）。
7. `ending` — エンディング。

## 4. 時間と1日の流れ

- 時間区分は `"morning" | "noon" | "evening" | "night"`（朝・昼・夕・夜）。
- 1日は「いえ」で `morning` から始まる。
- **地図から別の場所へ移動した時点で時間が1区分進む。**
  - `morning` のとき最初のスポットへ出かける移動では**時間を進めない**
    （いえ → 最初のスポットは「朝に出かける」扱い）。
  - 以降、スポット → 別スポットの移動ごとに `morning → noon → evening → night` と進む。
  - つまり1日に散策できるのは最大4回（朝・昼・夕・夜に各1スポット）。
  - 同じスポットに留まっている間は時間が進まない。
- `night` のスポットを出ると自動的に帰宅し、`dayend` へ。その後 `day += 1`、`morning` に戻る。
- 日数に上限はない。ゲームオーバーは存在しない。
- 時間が進むと、「逃げた」記録（§6）はすべてリセットされる。

## 5. スポットとマップ

スポット4つ: `shoutengai`（商店街）／`kawazoi`（川沿い）／`danchi`（団地）／`ekimae`（駅前）。

- タイルサイズ 24（論理px）。マップは **24 × 32 タイル**（= 576 × 768 論理px）。
- タイル配列は `src/data/spots.ts` に二次元配列のリテラルで直接書く。
  タイル種別は最低これだけ:
  `0` 通行可（地面）／`1` 壁・建物（通行不可）／`2` 通行可（草・砂利など見た目違い）／
  `3` 通行不可（水路のふち・側溝など）／`4` 通行可（屋内床・踊り場など）
- カメラはプレイヤー追従。マップ端でクランプして外を見せない。
- プレイヤーは半径 6 の円で当たり判定。軸ごとに分離して解決し、壁ずりができること。
- プレイヤー速度: 通常 **70 px/s**、忍び足 **28 px/s**。
- 各スポットには「違和感」オブジェクト（自販機、シャッター、側溝のふた、のぼり旗、
  団地の踊り場など）を図形で配置する。こひとの出現位置はこのオブジェクトに紐づける。

## 6. こひと

### 定義（`src/data/kohito.ts`）

| id | 名前 | スポット | 時間 | 手がかり |
|---|---|---|---|---|
| `urasumi` | じはんきウラスミ | ekimae | night | 釣り銭口から指が出ている |
| `haritsuki` | シャッターハリツキ | shoutengai | noon | シャッターの模様が1か所だけ呼吸している |
| `dobunozoki` | ドブノゾキ | kawazoi | morning | 側溝のふたの穴から目玉が見えている |
| `noboriyurashi` | ノボリユラシ | shoutengai | evening | 風がないのにのぼり旗が揺れている |
| `kagebousi` | ダンチカゲボウシ | danchi | night | 影はあるのに本体がいない |
| `tarejiri` | かくれたれじり | kawazoi | evening | 物陰から半透明の尻がはみ出している |

- 該当するスポット×時間に入ったときだけ、そのこひとが固定位置に出現する。
- MVP では**歩き回らない**（その場での待機モーションのみ）。
- `tarejiri` は §8 の特別扱い。

### 警戒度（awareness: 0〜1）

毎フレーム（dt 秒）で更新する。`d` = プレイヤーとこひとの距離（論理px）。

```
足音の半径 noiseRadius:
  静止中       = 0
  忍び足       = 30
  通常歩行     = 90

足音による増加:
  d < noiseRadius のとき  awareness += (1 - d / noiseRadius) * rate * dt
    rate = 通常歩行 0.5 /s、忍び足 0.25 /s

カメラを構えている間の追加増加（長押し中のみ）:
  awareness += 0.35 * (1 - clamp(d / 160, 0, 1)) * dt

上のどちらの増加も起きなかったフレーム:
  awareness -= 0.20 * dt   （下限 0）

awareness は 0〜1 にクランプする。
```

- `awareness >= 1` になったら **逃げる**: 0.6 秒の逃走モーションの後に消える。
  その「スポット×時間区分×こひと」は時間が進むまで再出現しない（§4 でリセット）。
- 警戒度はこひとの頭上に3段階（落ち着き／気にしている／警戒）で表示する。
  数値は出さない。

### 決定的瞬間（特別行動）

- 出現中、こひとは待機状態で過ごし、**6秒ごとの判定で 25% の確率**で
  特別行動に入る（持続 **1.5 秒**）。終わると待機に戻る。
- 特別行動は id ごとに1種類（例: ウラスミは釣り銭口から指を舐める、
  ドブノゾキはあくびをする、ハリツキはシャッターから半身をはがす 等）。
  見た目が明確に変わるように描く。
- 特別行動中にシャッターを切ると「決定的瞬間」が成立する（§7）。

## 7. 撮影と採点

### カメラ画面

- `field` でこひとへ一定距離（**120 px 以内**）に近づくとカメラアイコンが出る。
  カメラボタン長押しで `camera` へ。
- カメラ画面はスマホのカメラ風 UI。画面中央に**ファインダー枠**
  （論理 216 × 288、画面中央に配置）を描く。
- カメラ画面では、プレイヤーは移動できないが**向き（画角）は左右にわずかに振れる**。
  実装を簡単にするため、カメラ画面はフィールドの現在の見た目を
  プレイヤー位置から拡大表示（ズーム 1.6 倍）したものとし、
  スティック左右で画角を ±48 px 分だけパンできる、とする。
- 押している間ピントが合う。離した瞬間に撮影 → 採点 → 結果表示 → `field` に戻る。

### 採点（`src/game/photo.ts` の純関数として実装）

```ts
export type Framing = "miss" | "partial" | "half" | "full";

export interface ShotInput {
  /** こひとの見た目の矩形（カメラ画面の論理座標） */
  subject: { x: number; y: number; w: number; h: number };
  /** ファインダー枠（カメラ画面の論理座標） */
  finder:  { x: number; y: number; w: number; h: number };
  /** 長押しした時間（ミリ秒） */
  heldMs: number;
  /** プレイヤーとこひとのワールド距離（論理px） */
  distance: number;
  /** シャッターの瞬間、こひとが特別行動中だったか */
  moment: boolean;
}

export interface ShotResult {
  framing: Framing;
  coverage: number;   // 0..1
  focus: number;      // 0..1
  distScore: number;  // 0..1
  moment: boolean;
  score: number;      // 0..100（整数）
  rank: "S" | "A" | "B" | "C" | "D" | "fail";
}
```

計算式（この通りに実装する）:

```
coverage = (subject と finder の重なり面積) / (subject の面積)
  subject の面積が 0 以下なら coverage = 0

framing:
  coverage >= 0.95 → "full"
  coverage >= 0.50 → "half"
  coverage >  0    → "partial"
  それ以外          → "miss"

focus     = clamp(heldMs / 1200, 0, 1)
distScore = clamp((200 - distance) / 160, 0, 1)

framingWeight: full = 1.0 / half = 0.6 / partial = 0.25 / miss = 0

framing === "miss" のとき:
  score = 0, rank = "fail"
それ以外:
  raw   = 100 * (0.40 * framingWeight + 0.30 * focus + 0.20 * distScore)
          + (moment ? 20 : 0)
  score = round(clamp(raw, 0, 100))
  rank  = score >= 85 ? "S" : score >= 70 ? "A" : score >= 50 ? "B" : score >= 25 ? "C" : "D"
```

### アルバムのメモ段階

こひとごとに `stage: 0 | 1 | 2 | 3` を持ち、**一度上がったら下がらない**。
1枚の写真で到達する段階は:

```
stage 1「目撃」  : framing !== "miss"
stage 2「生態メモ」: (framing === "half" || framing === "full") かつ focus >= 0.6
stage 3「鳴き声」 : framing === "full" かつ (focus >= 0.9 または moment === true)
```

- `stage >= 2` に達した時点で、そのこひとの**ヒントを入手**する（§8）。
  雑な写真ではヒントはもらえない。
- アルバムはこひとごとに**最高スコアの1枚**を保持する（`ShotResult` と撮影時の
  日数・時間区分・スポットを記録）。写真そのものは保存せず、記録から
  「それっぽい1枚」を図形で再現描画する。

## 8. 推理とかくれたれじり

### ヒントによる絞り込み（`src/game/deduction.ts` の純関数）

候補は 4スポット × 4時間区分 = 16マス。ヒントは候補を消していく。

| ヒント元 | 消す候補 |
|---|---|
| `urasumi` | 時間が `morning` または `noon` のマス |
| `haritsuki` | スポットが `shoutengai` のマス |
| `noboriyurashi` | スポットが `danchi` のマス |
| `kagebousi` | スポットが `ekimae` のマス |
| `dobunozoki` | 時間が `night` のマス |

ヒントの文面は `src/data/text.ts` に、GAME_DESIGN.md §3 の表の通りに入れる。

```ts
export function remainingCandidates(hints: KohitoId[]): Candidate[];
// 5つ全部そろうと長さ 1 になり、その要素は { spot: "kawazoi", time: "evening" }
```

- アルバムの「すいり」タブで 4×4 のマス目を描き、消えた候補に×を付ける。
  残りが1マスになったら、そのマスを強調して「ここだ」と示す。
- **残り候補が1マスになるまで、`tarejiri` は出現しない。**
  代わりに各スポットへ「通った跡」（湿ったシャッター／しずくの跡）を
  1〜2個ランダムに描く。撮影対象ではなく、雰囲気のための演出。

### かくれたれじりの撮影（クライマックス）

`kawazoi` × `evening` に出現。挙動:

1. **隠れ状態**: 物陰（水路のふち）から**半透明の垂れた尻だけ**がはみ出している。
   この状態では採点対象の矩形は「尻だけ」なので、どう撮っても `coverage` は
   `full` に届かない（= 全身写真にならない）。
2. **出てくる条件**: プレイヤーが距離 **60〜120 px** の範囲にいて、
   `awareness < 0.5` の状態が **連続 4 秒**続くと、ゆっくり物陰から出てくる。
3. **全身状態**: 出てきてから **8 秒間**、全身が見える。この間に
   `framing === "full"` の写真を撮れば **クリア**。
4. 8秒経つと隠れ状態に戻る（条件を満たせばまた出てくる）。
5. 途中で `awareness >= 1` になったら逃げる。その日の夕にはもう出ない
   （翌日の夕に再出現）。

クリアすると `ending` へ。

### エンディング（`ending`）

雨は降らせない。図形アニメーションで次の順に見せる:

1. たれじりが干上がった水路に座り込む。
2. 尻からしずくが落ちて、小さな水たまりができていく。
3. ほかのこひとたちが物陰からそろそろと集まり、水たまりを囲む。
4. 締めのテキスト（`text.ts`）と「かかった日数」を表示。「アルバムを見る」で `album` へ。

## 9. セーブ

- `localStorage` キー: `"kohitosagasi.save.v1"`
- 保存する内容:

```ts
export interface SaveData {
  version: 1;
  day: number;                       // 1 以上
  time: TimeSlot;
  location: "home" | SpotId;
  album: Record<KohitoId, AlbumEntry | undefined>;
  hints: KohitoId[];                 // 重複なし
  cleared: boolean;
  clearedDay: number | null;
}
```

- 保存タイミング: 撮影の採点直後、時間が進んだとき、`dayend`、クリア時。
- 読み込み時は**必ず検証する**。`version` が違う／JSON が壊れている／
  想定外の id が入っている場合は、例外を投げずに**新規セーブとして扱う**
  （`loadSave()` は常に有効な `SaveData` を返す）。
- `localStorage` が使えない環境（プライベートモード等）でも落ちないこと。
  読み書きを try/catch で包み、失敗したらメモリ上だけで進行する。
- タイトルの「はじめから」はセーブを消す前に確認を出す。

## 10. 仮絵の方針（`src/render/`）

- 色は `palette.ts` に集約。日照りのまち: くすんだベージュ、コンクリ灰、
  乾いた緑、色あせたのぼり旗の赤。こひとは半透明の肌色〜灰緑。
- 時間区分ごとに画面全体へ色を乗せる（朝: 薄い青白、昼: 明るく白っぽい、
  夕: 橙、夜: 暗い青 ＋ 自販機だけ光る）。
- こひとは「ゆるキモ」を図形で出す。丸・楕円・ベジエで、
  目は多すぎるか少なすぎるか、体のどこかが半透明か濡れている、のどちらかを満たす。
  グロテスクにはしない（子どもが遊べる程度）。
- たれじりの尻は**桃型にしない**。餅／水まんじゅう的に、下へ垂れて伸びる
  半透明のかたまりとして描く（`globalAlpha` と縦に潰した楕円の重ねで表現）。
- 待機モーションは sin 波で上下または伸縮させる程度でよい。

## 11. テスト（`tests/`、Vitest）

純粋ロジックを必ずテストする。最低限これだけは書く。

`photo.test.ts`
- `coverage` が 0 / 部分 / 半分 / 完全の各ケースで `framing` が期待通り
- `framing === "miss"` のとき `score === 0` かつ `rank === "fail"`
- `focus` が `heldMs` 0 / 600 / 1200 / 3000 で 0 / 0.5 / 1 / 1（上限）になる
- `distScore` が distance 20 / 120 / 200 / 300 で 1 / 0.5 / 0 / 0 になる
- 全身・ピント満点・至近・決定的瞬間で `rank === "S"`
- 同じ入力で `moment` を true にするとスコアが 20 上がる（上限 100 でクランプ）
- 段階判定: stage 2 の境界（`focus === 0.6`）が含まれる、`partial` では stage 2 にならない

`deduction.test.ts`
- ヒント 0 個で候補 16
- ヒント1つずつ追加して 8 → 6 → 4 → 2 → 1 と減る（GAME_DESIGN.md §3 の順）
- 5つそろうと `{ spot: "kawazoi", time: "evening" }` のみ
- ヒントの順番を入れ替えても最終結果が同じ
- **5つのうちどの4つを選んでも**候補が2個以上残る（＝5つ全部必要であることの確認。
  5通りすべてを総当たりで検証する）

`kohito.test.ts`
- 静止していると awareness が増えない（むしろ減る）
- 通常歩行で至近距離だと忍び足より速く awareness が増える
- `noiseRadius` の外では awareness が減る
- カメラ長押し中は追加で増える
