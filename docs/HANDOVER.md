## 一人称3D試作「ほほもちの朝」　2026-11-23

11月28日、持ち主が11月27日に採用した三面図 `hohomochi-20261127-v01` の顔・肌・背中の模様を、頬と胴をつないだ暫定3D造形に投影しました。手足と尾は立体で、手と木の実が独立して動きます。朝のしぐさの合間に振り向き、道から背中を観察できます。

配布するメッシュと肌の画像は `src/prototype3d/assets/hohomochi.glb` に同梱しています。再作成する場合は、NumPy、Pillow、OpenCV が使える Python で `python scripts/model_hohomochi.py <approved-hohomochi-three-view.png>` を実行します。採用原画の SHA-256 を照合してから作成します。通常のゲームのビルドには Python や原画は不要です。

スマートフォンの試遊URLは [3D版GitHub Pages](https://takahashitakashi110-debug.github.io/kohitosagasi-3d-play/) です。左下の移動スティックと景色のドラッグを同時に使えます。撮影とズームは画面ボタンにあります。公開用は `npm.cmd run build:3d-pages` で作り、`dist/3d-pages/` の中身を [配布専用リポジトリ](https://github.com/takahashitakashi110-debug/kohitosagasi-3d-play) の `gh-pages` ブランチ直下へ配信します。戻す場合は配布コミットをrevertします。テストは `npm.cmd run e2e -- touch3d.spec.ts` で縦・横のタッチ操作と写真復元を検査します。

[依頼 #28](https://github.com/takahashitakashi110-debug/kohitosagasi/issues/28) と [PR #27](https://github.com/takahashitakashi110-debug/kohitosagasi/pull/27) を使用。作業ブランチは `codex/hohomochi-p0`、分岐元は本流 `4496b6e`。[P0の受入条件と後続設計](./REQUEST_P0_HOHOMOCHI.md) が3D側の引き継ぎ先です。この節以降に記載した従来のゲーム仕様は2D版のものです。

- `prototype3d.html` が入口です。TypeScript、Three.js 0.180.0、WebGL 2を使います。自室と短い道は連続した空間です。植え込みには、手元の実、葉の上の磨かれた実、任意で拾って返す実があります。朝以外にも痕跡を調べられます。
- カメラは描画したメッシュにレイを飛ばして、頬や実の画面内での見え方と遮蔽を検査します。その瞬間のWebGLキャンバスのみを実画像にします。ピント・距離・自然動作の周期は `src/prototype3d/rules.ts` にあります。
- IndexedDB `kohitosagasi-3d-p0-v1` の `photos` と `journal` に写真Blobと進行を同じトランザクションで保存します。展示・メモ・しおりは写真IDへ結び付けます。最後に選んだしおりを次の観察に使えます。保存が失敗しても写真と変更が画面に残り、再試行できます。
- WindowsのChromeで1280×720・1920×1080を検査。新旧の型チェック、単体445件、両HTMLのビルド、実ブラウザ14件（3Dが10件、既存2Dが4件）が通りました。二枚の実画像のSHA-256、再読込した選択画像、3Dフレーム上の色も比較しています。一枚目で出会い・生態が揃い、メモも交流もせず展示できる経路も通しました。
- CIの撮影検査では痕跡を調べてから一歩下がって構えます。テストが前進キーを離すのに遅れて実が画面外になったとき、生態判定は正しく不成立でした。再試行の検査では、失敗通知と未確定のDBを確認してから書き込みを再許可します。ゲーム内でも画像の取り込み中を表示し、ピントとしぐさには歩幅とは別の経過時間を使います。
- ソフトウェア描画のCIでは画面サイズを順番に検査します。撮影後に「保存済み」が出てからDB内の実画像を照合し、木の実を拾うときは操作案内が見える距離まで歩きます。
- PCのしぐさ撮影2シナリオではPlaywrightの時計で表示フレームを進め、ファインダーに出た姿勢を保って実マウス入力を送ります。公開URLのタッチ検査は実時間で撮影します。
- `npm.cmd run e2e` は4173番で一時配信します。証跡は `test-results/` 内の各画面サイズのディレクトリに生成されます。普段の試遊はREADMEの5183番で開いてください。ポートはブラウザの保存先の一部です。
- 頬・手・木の実の造形と音は仮素材です。正式な素材制作は素材チャットが担当します。10〜15分の体験時間、痕跡の発見しやすさ、キャラクターへの愛着は人による試遊が残っています。実機スマートフォン、Firefox、Safariは未検証です。夕の折り葉、未交流からの裏ステージ、主役撮影後の明示選択は後続のAC12〜AC15です。

## 4. 決まっていること（と、その理由）

設計 v0.3 の未決事項6件は全部決定済みです。**理由も含めて覆さないでください。**

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 時間進行 | スポット移動で1区分進む | 待ち時間ゼロ。狙った時間帯へ行けるので「ヒントを元に計画する」遊びになる |
| 出現条件 | ヒント5つの消去法で「川沿い×夕」に確定 | アルバムのメモがそのまま推理表になる |
| エンディング | 雨は降らせない。水たまりだけ | 救済をこひとに背負わせない。観察ゲームらしい幕切れ |
| 撮影操作 | 長押しでピント → 離してシャッター | 片手で遊べて、評価軸4つが自然に全部乗る |
| 主人公 | 夏休みにあつぎへ来た子ども | よそ者だから「まちの違和感」に気づける＝こひとが見える理由 |
| ライブラリ | 使わない（素の TS + Canvas 2D） | MVP の規模に対して過剰。仮絵と相性がよい |
| タイトル | こひとさがし | 「さがす（捕まえない）」が差別化方針そのもの |

**差別化方針**（既存作品と被らせないための約束）も維持してください。

- こひとは**捕まえない**。罠もない。観察手段は写真だけ
- 「図鑑」ではなく「あつぎこひと観察アルバム」
- たれじりの尻は桃型にしない。餅／水まんじゅうのように垂れて伸びる半透明
- 名前はカタカナ複合語ばかりにしない（ひらがなを混ぜる）
- 実在の地名・店名・施設名を使わない

## 6. 触るときの地雷（重要）

### 地雷1: 採点式の重みは合計 0.9

`src/game/photo.ts` の重みは 範囲 0.40 / ピント 0.30 / 距離 0.20 で、
**決定的瞬間なしの満点は 90 点**です。S は 85 点以上なので、
決定的瞬間を引かなくても S は取れます（運に依存させないための意図）。
重みを足し引きするとランクの分布が変わるので、`tests/photo.test.ts` も一緒に直してください。

### 地雷2: こひとを足す／配置を変えると、推理が壊れる

5つのヒントは「どの4つを選んでも絞りきれない」ように組んであります。
こひとを増やす・ヒントを変える・正解マスを動かすと、この性質が簡単に崩れます。
`tests/deduction.test.ts` が総当たりで守っているので、**先にテストを直してから実装**してください。

### 地雷3: たれじりの絵を変えると、3か所が連動する

これが一番踏みやすいです。たれじりの見た目・判定・遮蔽が**別々の場所に数値で散っています**。

| 場所 | 内容 |
| --- | --- |
| `src/render/kohitoArt.ts` の `drawTarejiri` | たれじり本体の絵（隠れ時は胴を描かない） |
| `src/scenes/field.ts` の `drawWorld` 内の `fillRect(k.x - 18, k.y - 39, 28, 33)` | 隠れ時に胴を隠す遮蔽の矩形 |
| `src/data/kohito.ts` の `SUBJECT_BOUNDS.tarejiri`（`subjectRect` が参照） | 採点に使う被写体の矩形 `{left:-15, top:-37, w:35, h:62}` |
| `src/scenes/camera.ts` の `evaluateCamera` 内の `visibleFinder` | 隠れ時に「見えている尻の範囲」へ狭める矩形 |

**絵だけ直して採点側を放置すると、隠れているのに全身写真が撮れてしまい、
いきなりクリアできてしまいます。** 必ず4か所セットで直し、
`playthrough.test.ts` の「隠れた尻だけでは全身にならない」が通ることを確認してください。

### 地雷4: 表示文字列は `src/data/text.ts` にだけ置く

他のファイルに日本語をハードコードしないでください（コメントは日本語で可）。

> 対応内容: カメラ画面の中心を `cameraCenter()`（`src/game/world.ts`）で

1. **カメラが縦に振れず、上下からだと撮れない**（`src/scenes/camera.ts:17-21`、`src/main.ts` の camera 分岐）
   - カメラ画面は**プレイヤー中心**に 1.6 倍拡大し、パンは横 ±48（画面px）のみ。
   - 計算上、通常のこひと（44×46）を `full` で枠に収められるのは
     **縦のずれ約 67 px 以内・横のずれ約 75 px 以内**。
     一方カメラアイコンは距離 **120 px 以内**で出るので、
     真上／真下 70〜120 px から構えると「撮れるはずなのに全身が入らない」。
   - 直し方の案: カメラ画面の中心を「プレイヤー→対象こひと」の方向へ寄せる
     （例: 中心 = プレイヤー + (対象 − プレイヤー) × 0.6）か、縦パンも許す。
     どちらでも `subjectRect` と描画（`drawWorld` のカメラ表示）を**同じ式**で動かすこと。
   - 追加テスト: 真上 100 px のこひとに対し、パンを適切にすれば `framing === "full"` になる。

2. **リロードすると逃げたこひとがすぐ戻る**（`src/game/state.ts` の `SaveData`、`src/main.ts` の continue 処理）
   - `game.escaped` はメモリ上だけで、`SaveData` に入っていない。
     タイトルの「つづける」で `escaped.clear()` されるため、
     逃げられた直後にリロードすれば同じ時間区分で再挑戦できてしまう。
     たれじりの「逃げたらその日の夕にはもう出ない」も同じ抜け道で無効になる。
   - 直し方の案: `SaveData` に `escaped: KohitoId[]` を足し（時間が進んだら空にする）、
     `save.ts` の検証にも追加する。`version` を上げるか、欠けていたら空配列で補う。
   - 追加テスト: 逃走 → 保存 → 読み込み → 同じ時間区分の `enterField` で出現しない。
