# I: 町に住む、変わった生態の大人たち（試作へ統合）

## 目的

持ち主の追加依頼（2026-11-23）:
「夏休みの1週間だけおばあちゃんの住む町に遊びに来た」を設定へ反映する。
こひととは別に外れ判定のキャラを配置する。外れキャラは、変わった生態や
日課を持つ風変わりな大人たち。Runwayでキャラ画像も作成する。

持ち主の「今回を試作として完成まで進める」という追加指示を受け、設定文・画像素材に加え、
**4人の配置・連続コマ・外れ撮影と結果表示までPR #22へ統合**した。具体的な接続は依頼Jを参照。
1週間は物語の設定であり、7日目の強制終了や既存進行の変更は今回求められていない。

## 次回の実装案

- 人間の住人をこひとと別のデータ・描画・対象種別で管理する。
- 4スポットに1人ずつ置く。通れる場所に配置し、通行やこひとの観察を妨げない。
- 日課を観察でき、近づいて撮影すると「町の人でした」などの外れ結果を表示する。
- 外れでも罰は付けず、散策へ戻れる形を初期案とする。6体のこひとの記録、
  ヒント5つ、たれじりの解放・クリア条件には数えない。
- 複数の対象が近い場合の選択・優先順位を明示し、こひとを撮れなくしない。
- 住人の写真を保存する専用アルバムは本依頼の初期範囲に含めない。
- 日本語の表示は `src/data/text.ts` に集約し、画像はローカル同梱する。

## 変更してよい範囲（次回用）

住人用の新規データ・描画・状態・撮影対象分岐、既存画面への接続、text.ts、
住人用の新規テストとe2e、プレビュー、関連ドキュメント。
実装着手前に検査担当が具体的なパス・撮影対象の契約を確定し、WORKFLOW.md
§3-2に従い作業用ブランチとドラフトPRを用意する。PR #22ではこの接続を実装しない。

## 変えてはいけないもの

6体のID・日本語名・出現条件、既存の採点式、ヒントの推理、たれじりの隠れ判定、
セーブの後方互換性、通行判定、既存パレット・重要テストを弱めない。

## テスト・受入条件（次回）

- 4人をそれぞれの場所で見つけ、日課の動きと人間だとわかる姿を確認できる。
- 住人を撮影すると外れ結果になり、既存こひとアルバム・ヒント・クリアは変化しない。
- 住人の近くにいるこひとも撮影でき、6体の撮影・たれじりの隠れ／全身が従来どおり成立する。
- 390×844 / 360×640の実ブラウザで散策・撮影・結果・復帰を検証する。
- 画像失敗時も操作でき、外部通信・404・JavaScriptエラーがない。
- 型チェック、既存テストを含む単体テスト、ビルド、e2eを実行し、PRに結果を記録する。
